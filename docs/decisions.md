## Вход студента — личная ссылка от куратора

**Почему.** Ревью #36/#37 (14.10.2026) нашло дыру: когда студент сам вводит ФИО и год рождения, несовершеннолетний может ввести данные однокурсника и получить его согласие родителя — или написать год 2000 и обойти правило для младше 18. Сверка по ФИО это не закрывает: ФИО однокурсника знают все.

**Правила.**

1. **Студента заранее создаёт куратор** (лучше списком от колледжа): ФИО, дата рождения (если колледж не даёт — год), группа, отметка «согласие родителя получено» для младше 18 (ФИО родителя и где лежит бланк). Отдельная таблица «список колледжа» и сверка по ФИО не нужны.
2. **У каждого студента своя одноразовая ссылка**, привязанная к заранее созданному студенту (в базе каждая ссылка принадлежит одному студенту — одноразовость следует из этого, отдельного лимита нет). При первом входе к нему привязывается Telegram, после этого ссылка ни для кого больше не работает. У студента одна действующая ссылка; после отзыва куратор выдаёт новую.
3. **Студент ничего не вводит и не меняет** в своих личных данных. Заметил ошибку в ФИО — кнопка «Сообщить об ошибке» → обращение куратору; исправляет только куратор.
4. **Общая ссылка группы есть только в прототипе** (браузерное демо без сервера). На сервере её нет: база не даёт создать ссылку, не принадлежащую конкретному студенту.
5. **Раздача в кабинете куратора:** у каждого студента — «Скопировать ссылку» и QR (показать на паре, студент сканирует свой). Видно, кто уже вошёл, а чья ссылка ещё не использована. Ссылку отправляют лично, не в общий чат; утекла или потерялась — куратор отзывает и выдаёт новую.
6. **Младше 18 без отметки согласия родителя** — демо без сохранения; куратор поставил отметку — всё включается. Согласие родителя из Telegram студента не принимаем.
7. **18 лет** считаем по дате рождения (колонка в 004) — требование согласия родителя снимается в день рождения по времени Казахстана; родившимся 29 февраля — с 1 марта в невисокосный год. Если колледж даёт только год — считаем по году, до конца года студент несовершеннолетний. Дату сервер наружу не отдаёт, студент её не меняет. Кабинет передаёт дату как ГГГГ-ММ-ДД, год берётся из неё. Вопрос о дате рождения — в ТЗ, А4.
8. **Куратора приглашает администратор колледжа** личной ссылкой со сроком действия.

**Что меняется.** #35 — личные приглашения к заранее созданному студенту, дата рождения; общей ссылки группы на сервере нет. #36 — согласие родителя отмечает куратор на студента, без списка и сверки. #37 — студент не вводит ФИО и год, всё приходит из приглашения. Кабинет (#9) — «Список группы», «Выдать ссылки» (копировать/QR, статус входа), «Согласия родителей».

## #7 — как проверяем код студента

**Прототип.** Код и тесты запускаются в браузере (Pyodide). Экран редактора — @svlab27-web.

**Пилот.** Отдельный проект Vercel без секретов: одна Python-функция принимает код и тесты, запускает их и возвращает результат. Экран редактора при переходе не меняется.

Правила:

1. **Зачётную оценку пишет только сервер.** Для самостоятельной (зачётной) задачи браузер отправляет код в `api/` → `api/` сам отправляет код и скрытые тесты в проверяющую функцию → получает результат → пишет в `attempts`. Для зачётной задачи браузер никогда не сообщает «тесты пройдены». Тренировочные шаги — см. правило 3.
2. **Проверяющая функция ограничена:** код студента запускается в отдельном процессе с лимитом времени (~3 с) и памяти; есть лимит запросов на студента; функцию вызывает только `api/` по общему ключу (ключ даёт только проверку кода — его утечка не страшна).
3. **Гибрид.** Тренировочные шаги проверяются в браузере (там подделка ничего не даёт), на сервер — только самостоятельная задача, которая идёт в зачёт. Результаты, проверенные в браузере в прототипе, помечаются в базе отдельно, чтобы не смешивать их с данными пилота.

## AI-тьютор — DeepSeek

**Подключение.** Переменные в Vercel (Production + Preview): `AI_PROVIDER=deepseek`, `AI_API_KEY` — ключ DeepSeek, `AI_MODEL=deepseek-flash`. Base URL — `https://api.deepseek.com` (формат OpenAI). Ключ — только в Vercel, в чат и код не пишем.

**Модель.** `deepseek-flash` (DeepSeek-V4.1-Flash, с 10.09.2026) — самая дешёвая модель в текущей линейке. Старые имена `deepseek-chat`, `deepseek-reasoner` и `deepseek-v4-flash` устарели (DeepSeek временно перенаправляет их на новые модели), в коде их не используем. Сверено с документацией DeepSeek 13.10.2026. При следующем переименовании меняем только `AI_MODEL`.

**Личные данные — главное правило.** Серверы DeepSeek в Китае, а среди студентов есть несовершеннолетние. Поэтому:

1. В DeepSeek уходят **только** вопрос студента и утверждённый материал урока (тексты шага, подсказки).
2. **Никогда** не отправляем ФИО, год рождения, Telegram ID, username, группу, `user_id` и другие личные данные. Поле `user` в запросе к API не заполняем.
3. Запрос собирает `api/` из `lessons.content`, а не из того, что прислал браузер. Вопрос студента перед отправкой проходит фильтр: телефон, e-mail, номер документа вырезаем.
4. Эталоны, скрытые тесты и решение самостоятельной задачи в запрос не кладём — AI не должен выдать ответ на зачётную задачу.
5. Журнал диалога хранится у нас в `ai_messages` (провайдер, модель, токены, стоимость, язык). Дневной лимит на студента `api/` считает по этой таблице.
