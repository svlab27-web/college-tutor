## #7 — как проверяем код студента

**Прототип.** Код и тесты запускаются в браузере (Pyodide). Экран редактора — @svlab27-web.

**Пилот.** Отдельный проект Vercel без секретов: одна Python-функция принимает код и тесты, запускает их и возвращает результат. Экран редактора при переходе не меняется.

Правила:

1. **Зачётную оценку пишет только сервер.** Для самостоятельной (зачётной) задачи браузер отправляет код в `api/` → `api/` сам отправляет код и скрытые тесты в проверяющую функцию → получает результат → пишет в `attempts`. Для зачётной задачи браузер никогда не сообщает «тесты пройдены». Тренировочные шаги — см. правило 3.
2. **Проверяющая функция ограничена:** код студента запускается в отдельном процессе с лимитом времени (~3 с) и памяти; есть лимит запросов на студента; функцию вызывает только `api/` по общему ключу (ключ даёт только проверку кода — его утечка не страшна).
3. **Гибрид.** Тренировочные шаги проверяются в браузере (там подделка ничего не даёт), на сервер — только самостоятельная задача, которая идёт в зачёт. Результаты, проверенные в браузере в прототипе, помечаются в базе отдельно, чтобы не смешивать их с данными пилота.

## AI-тьютор — DeepSeek

**Подключение.** Переменные в Vercel (Production + Preview): `AI_PROVIDER=deepseek`, `AI_API_KEY` — ключ DeepSeek, `AI_MODEL=deepseek-flash`. Base URL — `https://api.deepseek.com` (формат OpenAI). Ключ — только в Vercel, в чат и код не пишем.

**Модель.** `deepseek-flash` (DeepSeek-V4.1-Flash, с 10.09.2026) — самая дешёвая модель в текущей линейке. Старые имена `deepseek-chat`, `deepseek-reasoner` и `deepseek-v4-flash` устарели (DeepSeek временно перенаправляет их на новые модели), в коде их не используем. Сверено с документацией DeepSeek 13.10.2026. При следующем переименовании меняем только `AI_MODEL`.

**Личные данные — главное правило.** Серверы DeepSeek в Китае, а среди студентов есть несовершеннолетние. Поэтому:

1. В DeepSeek уходят **только** вопрос студента и утверждённый материал урока (тексты шага, подсказки).
2. **Никогда** не отправляем ФИО, год рождения, Telegram ID, username, группу, `user_id` и другие личные данные. Поле `user` в запросе к API не заполняем.
3. Запрос собирает `api/` из `lessons.content`, а не из того, что прислал браузер. Вопрос студента перед отправкой проходит фильтр: телефон, e-mail, номер документа вырезаем.
4. Эталоны, скрытые тесты и решение самостоятельной задачи в запрос не кладём — AI не должен выдать ответ на зачётную задачу.
5. Журнал диалога хранится у нас в `ai_messages` (провайдер, модель, токены, стоимость, язык). Дневной лимит на студента `api/` считает по этой таблице.

## Вход студента и согласие родителя

Личность студента берём из документов колледжа, а не со слов студента (миграции `004_personal_invites.sql`, `005_parental_consent.sql`).

1. **Куратор вносит группу один раз** — лучше списком от колледжа: ФИО, год рождения, отметка о согласии родителя для младше 18 (где лежит документ: «личное дело № …», «список при зачислении, приказ № …»). Сканы не храним — бумага остаётся в колледже.
2. **Каждому студенту — личная одноразовая ссылка.** Куратор выдаёт её лично: «Скопировать» или QR на каждого студента в кабинете (показать на паре). В кабинете видно, кто уже вошёл, а чья ссылка не использована. Общей ссылки группы для реальных студентов нет.
3. **При первом входе** ссылка привязывается к Telegram студента. Студент свои ФИО и год не вводит и не меняет. Ссылка утекла или потерялась — куратор отзывает её и выдаёт новую.
4. **Согласие на обработку ПД** студент даёт сам в приложении. **Младше 18 без отметки куратора о согласии родителя** — демо без сохранения прогресса; куратор отметил — всё включается. Согласие родителя из Telegram студента не принимаем — проверить, что это родитель, нельзя.
5. **Ошибка в ФИО** — студент жмёт «сообщить об ошибке», исправляет только куратор.
6. **Исполнилось 18** — по году рождения согласие родителя больше не требуется. Год, в котором исполняется 18, пока считаем несовершеннолетним; если у колледжа есть дата рождения — перейдём на неё (вопрос в ТЗ, А4).
7. **Куратора приглашает администратор колледжа** — личной ссылкой со сроком.

Нужно от колледжа (ТЗ, часть А): подтверждение юриста, что их согласие покрывает наш сервис (договор поручения на обработку), форма бланка и списка группы, способ передачи списка (не в общий чат и не открытым файлом по почте), администратор сервиса.
