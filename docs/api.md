## Коротко

- Сервер — **TypeScript, обработчики вида `Request → Response`**, не привязанные к платформе: те же файлы работают как Vercel Function (прототип) и как обычный Node-сервер `server/index.ts` (продакшен на своём сервере в РК, `docs/production.md`).
- База — **через `DATABASE_URL` и postgres.js**, без supabase-js (решение из #33): переезд с Supabase на свой PostgreSQL — замена адреса, а не переписывание. Модуль базы один — `api/_lib/db.ts`.
- Mini App ходит **только** в `/api/*` и в каждом запросе передаёт `initData` Telegram в заголовке `X-Telegram-Init-Data`. Сервер проверяет подпись и по ней узнаёт студента.
- Правильные ответы, тесты и варианты **никогда не уходят в браузер** — проверка и запись результата только на сервере.
- В обычном браузере (без Telegram) прототип продолжает работать как демо на localStorage — для показа.

## 0. Что нужно до первой строки кода

1. **Vercel:** Root Directory уже корень репозитория (`./`), `app` — Output Directory; это же записано в `vercel.json`. Функции из корневой `api/` Vercel видит — проверено на превью #34 (`/api/health`).
2. **Переменные окружения в Vercel** (Production + Preview), см. `.env.example`:
   - `DATABASE_URL` — Supabase → **Connect** → **Transaction pooler** (порт 6543, IPv4). Прямая строка `db.<ref>.supabase.co` работает только по IPv6 — Vercel её не видит. В postgres.js — `prepare: false`;
   - `BOT_TOKEN`, `TG_WEBHOOK_SECRET` — есть;
   - `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL` — есть (DeepSeek, `docs/decisions.md`);
   - `APP_URL` (кнопка бота), `BOT_USERNAME` (по умолчанию `tutornvl_bot`).
   Вписывает владелец Vercel; значения в чат и код не пишем.
3. **Лимит Hobby — 12 функций.** Одна функция `api/index.ts` на все `/api/*` (`vercel.json`: rewrite `/api/<путь>` → `/api?__path=<путь>`, функция восстанавливает путь), включая вебхук бота `/api/bot`. Общий код — в `api/_lib/` (файлы с `_` функциями не считаются).

## 1. Вход (#5)

```
Куратор заводит группу (лучше списком колледжа): ФИО, год рождения, отметка о согласии родителя
        → каждому студенту — личная одноразовая ссылка (кабинет: «Скопировать» / QR)
Студент → t.me/tutornvl_bot?startapp=<код своей ссылки>
        → Mini App открывается, в initData есть start_param = код
        → GET /api/me  (заголовок X-Telegram-Init-Data)
        → сервер: проверка подписи → ссылка привязывает Telegram к заведённому студенту
        → ответ: кто я, роль, группы, язык, что ещё нужно (согласие, согласие родителя)
```

**Проверка `initData`** (`api/_lib/auth.ts`):
- `secret = HMAC_SHA256(key="WebAppData", data=BOT_TOKEN)`;
- строка проверки — все поля кроме `hash`, по алфавиту, `key=value` через `\n`;
- `HMAC_SHA256(secret, строка) == hash` (сравнение за постоянное время);
- `auth_date` не старше 24 часов и не из будущего;
- `initDataUnsafe` и `username` для личности **не используем** — только `user.id` из проверенной строки.

**Личная ссылка** (миграция `004_personal_invites.sql`, #35; решение 14.10.2026): одна ссылка — один заранее заведённый студент (`invites.user_id`), одноразовая, у студента одна действующая ссылка. Код = `start_param` целиком, 16–64 символа `A-Z a-z 0-9 _ -`. Вход — одна транзакция (`api/_lib/invites.ts`): статусы `joined`, `already_yours` (своя ссылка повторно), `used` (ссылкой вошёл другой Telegram; название группы ему не показываем), `already_registered` (этот Telegram уже у другого студента, в том числе если две ссылки открыты одновременно), `expired`, `revoked`, `invalid`. Ссылка преподавателя — всегда со сроком. Утекла — куратор отзывает и выдаёт новую. Общей ссылки группы для реальных студентов нет. Преподавателя так же приглашает администратор колледжа. Демо-параметры `startapp=student` / `teacher` приглашениями не считаются; Telegram без личной ссылки — демо, в базу ничего не пишем.

**Ссылку перехватили — «отвязать Telegram»** (кабинет #9, кнопка — @svlab27-web). Если по ссылке студента вошёл чужой Telegram, «Новая ссылка» не поможет: студент уже привязан к чужому Telegram, а настоящий студент без входа не может даже написать куратору (403).

`POST /api/curator/students/:id/unlink` — только куратор группы этого студента (`group_members.role = 'teacher'` в той же группе) или админ. В одной транзакции:
- `users.telegram_user_id = null` — чужой Telegram больше не видит данные студента;
- все действующие ссылки студента отзываются (`invites.revoked_at = now()`);
- согласие на обработку ПД, данное с отвязанного Telegram, отзывается (`revoked_at`) — его давал, возможно, не студент; согласие родителя (отметка куратора) остаётся;
- прогресс и попытки остаются — они привязаны к `user_id`.

Ответ — `{ ok: true }`; дальше куратор выдаёт новую ссылку («Новая ссылка» / QR), студент входит и заново даёт согласие. В лог — кто, когда и какого студента отвязал (без Telegram ID).

**Первый вход:**
- ФИО и год рождения вносит **куратор** — студент их не вводит и не меняет (`POST /api/me` с ними → 409); ошибка — «сообщить об ошибке» (`POST /api/help`, `kind = name_error`);
- согласие на обработку ПД → `POST /api/consent` (`kind = personal_data`, текущая `doc_version`, `granted_via = telegram`, копия `telegram_user_id`); устаревшая версия текста → 409, показать заново;
- **младше 18** без согласия родителя — только демо без сохранения прогресса. Год, в котором исполняется 18, считаем несовершеннолетним — безопаснее;
- **согласие родителя отмечает куратор** по документам колледжа (миграция `005_parental_consent.sql`, #36): бумага или список, собранный при зачислении (`document_ref` — где лежит). Можно до первого входа студента. Из Telegram студента не принимаем.

**Бот** (`POST /api/bot`, вебхук с проверкой `X-Telegram-Bot-Api-Secret-Token`):
- ответ уходит прямо в ответе на вебхук — без исходящих запросов и без токена бота в коде обработчика;
- `/start <код>` → кнопка `t.me/tutornvl_bot?startapp=<код>` (тогда код придёт в `initData` подписанным);
- `/start` → кнопка `web_app` на `APP_URL`; `/help` → коротко, как пользоваться;
- в группах бот молчит; Telegram повторяет запрос при любом ответе, кроме 200, — поэтому на непонятное 200 без действия.
- Вебхук ставим после merge входа: `setWebhook` на `https://<домен>/api/bot` с `secret_token` (команда — в `docs/production.md`, п. 6).

## 2. Уроки, ответы, прогресс (#6)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | Жив ли сервер и доступна ли база (#34) |
| GET | `/api/me` | Профиль, роль, группы, язык, что не заполнено. По `start_param` — вступление в группу |
| POST | `/api/me` | Язык интерфейса (ФИО и год — только куратор) |
| POST | `/api/consent` | Согласие на обработку ПД |
| POST | `/api/bot` | Вебхук Telegram |
| GET | `/api/lessons` | Опубликованные уроки + прогресс студента |
| GET | `/api/lessons/:id?lang=kk` | Урок без серверных полей; язык: `kk` из `lesson_translations` (если `approved`), иначе основной |
| POST | `/api/answer` | Проверить ответ, записать `attempts`, обновить `progress` |
| POST | `/api/hint` | Следующая подсказка (лестница 1→2→3), запись в `hint_events`; в самостоятельной задаче — отказ |
| POST | `/api/help` | Обращение куратору: «ошибка в ФИО» — сразу; «нужна помощь» — когда есть согласия (иначе 403) → `help_requests` (+ уведомление в Telegram, позже) |

**Что вырезается из урока перед отправкой в браузер:** `expected`, `tests`, `solution`, `number_part.expected`, `variants`, `free_input`, `common_mistakes.pattern`. Остаётся то, что студент видит: тексты, `options`, `hints` (выдаются по одной через `/api/hint`), `checks` (таблица кассы и так показывает ожидаемое).

**`POST /api/answer`** — тело `{ lesson_id, step_id, answer, request_id }`:
- `choice` — индекс; `number` — `|ответ − value| ≤ tolerance` с тем же разбором чисел, что в прототипе (пробелы, ₸, м², кв.м…); `number_part` — обе части должны быть верны;
- самостоятельная задача: вариант выбирает **сервер** (детерминированно по студенту и уроку), браузер получает только тексты своего варианта;
- `request_id` (uuid от клиента) + `unique (user_id, request_id)` — повтор запроса не создаёт дубль;
- ответ: `{ correct, feedback, progress }`, где `feedback` — из `success` / `common_mistakes` / общий;
- пишем `attempts.language` и `is_independent`; прогресс сохраняем, только если `can_save_progress` (согласия есть);
- в прототипной фазе результаты из браузерной проверки помечаем отдельно (решение по #7).

### Минимум к показу 16.10 — контракт

Отличия от плана выше (договорились 15.10, уточнено по ревью #48): `/api/hint` пока нет — `hints` приходят в уроке целиком, лестницу по одной держит фронт. `checks` (таблица проверки) и `free_input` (код, формулы) выдают ответ шага, поэтому приходят **только после верного ответа**: в ответе `POST /api/answer` (поле `reveal`) и потом в `GET /api/lessons/:id` у пройденных шагов; `free_input` — без `solution`, проверяется в браузере и в прогресс не идёт, в самостоятельной не приходит вовсе. AI-подсказок нет.

Кто: любой с проверенным `initData`. Незаведённый Telegram (демо) получает уроки и проверку ответа, но ничего не сохраняется. Сохраняем попытки и прогресс, только если `can_save_progress` (как в `/api/me`). Студенту — только опубликованные уроки (`is_published`); куратору и админу — все, с `is_published: false`.

Язык: `?lang=kk` → перевод из `lesson_translations`, если он `approved`; иначе основной текст. Какой язык отдан — в поле `language`.

**`GET /api/lessons?lang=ru`**

```json
{
  "can_save_progress": true,
  "lessons": [
    {
      "id": "8b0e…", "subject": "python", "slug": "01-skidka-v-kafe",
      "title": "Почини скидку в студенческом кафе", "skill": "Условия и граничные значения",
      "minutes": 10, "week": 4, "order": 1, "language": "ru", "is_published": true, "steps_total": 4,
      "progress": { "completed_steps": 1, "current_step": "s2", "completed_at": null }
    }
  ]
}
```

`progress` — `null`, если студент урок не начинал или прогресс не сохраняется.

**`GET /api/lessons/:id?lang=ru`** — урок без серверных полей + прогресс:

```json
{
  "can_save_progress": true,
  "lesson": {
    "id": "8b0e…", "subject": "python", "slug": "01-skidka-v-kafe", "title": "…", "skill": "…",
    "minutes": 10, "story": "…", "material": "…", "language": "ru", "is_published": true,
    "steps": [
      { "id": "s1", "title": "…", "prompt": "…", "answer_type": "choice", "options": ["…", "…"],
        "hints": ["намёк", "вопрос", "пример"], "simple": "…" },
      { "id": "s3", "title": "…", "prompt": "…", "code": "…", "answer_type": "choice", "options": [">", ">=", "<", "=="],
        "hints": ["…"],
        "checks": [{ "input": 999, "expect": 999 }], "free_input": [{ "prompt": "…", "answer_type": "code", "starter_code": "…", "tests": [{ "call": "…", "expect": 900 }] }] },
      { "id": "s4", "title": "…", "independent": true, "prompt": "текст выбранного сервером варианта",
        "answer_type": "choice", "options": ["…"], "number_part": { "label": "Сумма за заказ…, ₸" }, "hints": [] }
    ]
  },
  "progress": {
    "lesson_id": "8b0e…", "steps_total": 4, "completed_steps": 2, "completed": ["s1", "s2"],
    "current_step": "s3", "completed_at": null,
    "independent": { "solved": false, "first_try": null }
  }
}
```

Вырезано: `expected`, `number_part.expected`, `solution`, `variants`, `common_mistakes`; `checks` и `free_input` — у ещё не пройденных шагов (в примере s3 уже пройден). В самостоятельной задаче `prompt` / `options` / `number_part.label` — уже выбранного варианта. Список уроков — в порядке плана: предмет, `week`, `order`.

**`POST /api/answer`** — тело:

```json
{ "lesson_id": "8b0e…", "step_id": "s4", "request_id": "c1f5…-uuid", "hints_used": 0, "lang": "ru",
  "answer": { "choice": 1, "number": "1 700 ₸" } }
```

`answer`: `choice` — индекс варианта (число); `number` — строка или число (`"1 700 ₸"`, `"10,5 м²"`, `"0,125"`; запятая — всегда десятичный знак, тысячи — только пробелами; две запятые или запятая с точкой — «введите число»); шаг `choice` с `number_part` — `{ "choice": 1, "number": "1700" }`; шаг `number` с `number_part` — `{ "number": "3", "part": "5" }`. `request_id` — uuid, новый на каждое нажатие «Проверить»: повтор того же запроса возвращает прежний результат, тот же `request_id` с другим ответом или шагом — `409 request_reused`. `hints_used` — сколько подсказок открыто на этом шаге (0–3).

Ответ `200`:

```json
{
  "correct": false,
  "parts": { "choice": true, "number": false },
  "feedback": "Пока не так. Возьмите подсказку — готовый ответ не дадим.",
  "saved": true,
  "progress": { "lesson_id": "8b0e…", "steps_total": 4, "completed_steps": 3, "completed": ["s1", "s2", "s3"],
                "current_step": "s4", "completed_at": null, "independent": { "solved": false, "first_try": false } }
}
```

`parts` — только у шагов с `number_part`: `{ choice, number }` или `{ number, part }`. `reveal` — `{ checks?, free_input? }`, только при `correct: true`. `saved: false` и `progress: null` — демо или нет согласий. Самостоятельная у заведённого студента без согласий — `correct: null` и текст «проверим, когда включится сохранение» (чтобы нельзя было перебрать ответ до согласия); демо проверяется как обычно. Ошибки: `400 bad_answer` (не тот формат), `404 lesson_not_found` / `step_not_found`, `409 request_reused`, `422 browser_check` (тип ответа проверяется в браузере).

**`GET /api/curator/progress?group_id=`** — вкладка «Прогресс» (только чтение, доступ как у `/api/curator/students`):

```json
{
  "group_id": "…",
  "lessons": [{ "id": "8b0e…", "subject": "python", "slug": "01-skidka-v-kafe", "title": "…", "steps_total": 4 }],
  "students": [
    { "id": "…", "full_name": "Иванов Петр", "can_save_progress": false,
      "lessons": {
        "8b0e…": { "completed_steps": 2, "current_step": "s3", "completed_at": null,
                   "last_activity": "2026-10-16T09:12:00Z", "attempts": 5, "hints_used": 3,
                   "independent": { "solved": false, "first_try": null } }
      } }
  ]
}
```

`lessons` у студента — только начатые уроки. `first_try` — самостоятельная решена с первой попытки (`null` — ещё не пробовал).

## 2а. Кабинет куратора (#9, часть 1)

Личность — только из `initData`; `telegram_user_id` наружу не отдаём. Код: `api/_lib/curator.ts`, `api/_lib/routes/curator.ts`, тесты — `tests/curator.db.test.ts`.

## 3. Уроки из `content/` в базу

`scripts/sync-lessons.ts` (проверка — `scripts/lessons.ts`):

- `npm run lessons:check` — только проверка файлов, без базы. В CI — через тест `tests/lessons.test.ts` (проверяет настоящие файлы `content/`): схема `content/lesson.schema.json` + смысл (индекс ответа в пределах вариантов, у самостоятельной задачи нет подсказок, подсказок ≤ 3, id шагов не повторяются), имя файла ↔ `subject`/`slug`/`language`, перевод `.kk.json` совпадает с основным по «нетекстовым» полям (правила в шапке `003`).
- `npm run lessons:sync` — проверка + запись в базу из `DATABASE_URL`, одной транзакцией. Ошибка в любом файле — в базу ничего.
  - урок = одна запись `lessons (subject_id, slug, version = 1)`; повторный запуск обновляет её, `id` не меняется — попытки и прогресс не теряются; без изменений — ничего не пишет;
  - `is_published = status = 'approved'` (утверждает преподаватель), `approved_by` из файла; перевод — `lesson_translations` со своим статусом;
  - уроки, которых нет в `content/`, не удаляются (на них ссылаются попытки) — скрипт только сообщает.
- **План семестра (КТП)** — `content/plans/<slug>.json` (не урок, в `lessons` не пишется): недели по порядку, у каждой тема, часы, «знать», «уметь» и `lessons` — slug уроков. У урока из плана поля `week` и `order` (место в неделе) обязаны совпадать с планом — по ним приложение показывает уроки в порядке КТП (`order by (content->>'week')::int, (content->>'order')::int`). `lessons:check` проверяет: урок из плана существует, недели без пропусков, сумма часов = `hours_total`, урок с `week` не потерян из плана. Читаемый документ для преподавателя — `python3 scripts/plan-doc.py .` → `docs/plan-python-1-semestr.md`. В базу план пока не пишем — понадобится таблица для вкладки «Уроки» в кабинете.
- **Тесты кода** (`tests[].call`): выражение Python, которое вычисляется после запуска кода студента, результат сравнивается с `expect` через `==`. Особое значение `__stdout__` — весь вывод программы на экран (для заданий без функций, неделя 1).
- В `options` бывает перенос строки `\n` — это код из нескольких строк: показывать моноширинным блоком.

Запуск на базе прототипа (строку Transaction pooler не вставлять в чат и не сохранять в файлы — её спросит терминал, на экран не выводится; работает и в bash, и в zsh):

```bash
printf "Строка подключения: " && read -rs DATABASE_URL && echo && export DATABASE_URL && npm run lessons:sync; unset DATABASE_URL
```
