## Коротко

- Сервер — **Vercel Functions на TypeScript** в папке `api/`, база — Supabase через `service_role` (см. `docs/database.md`).
- Mini App ходит **только** в `/api/*` и в каждом запросе передаёт `initData` Telegram в заголовке `X-Telegram-Init-Data`. Сервер проверяет подпись и по ней узнаёт студента.
- Правильные ответы, тесты и варианты **никогда не уходят в браузер** — проверка и запись результата только на сервере.
- В обычном браузере (без Telegram) прототип продолжает работать как демо на localStorage — для показа.

## 0. Что нужно до первой строки кода

1. **Vercel собирает проект из папки `app/`** (Root Directory = `app`): `/` открывается, а `/README.md` и `/api/...` — 404. Функции из корневой `api/` Vercel так не увидит.
   Решение: в репо добавить `vercel.json` (`outputDirectory: "app"`), смержить, **потом** в настройках Vercel поменять Root Directory на корень репозитория. Порядок важен: пока Root Directory = `app`, корневой `vercel.json` игнорируется и ничего не ломает.
2. **Переменные окружения в Vercel** (Production + Preview), см. `.env.example`: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (legacy, `eyJ…`), `BOT_TOKEN` (уже есть), `TG_WEBHOOK_SECRET`. Вписывает владелец Vercel; значения в чат и код не пишем.
3. **Лимит Hobby — 12 функций.** Делаем один маршрутизатор `api/[...path].ts` + отдельный `api/bot.ts` для вебхука. Общий код — в `api/_lib/` (файлы с `_` функциями не считаются).

## 1. Вход (#5)

```
Студент → t.me/tutor_testbot?startapp=<токен приглашения>
        → Mini App открывается, в initData есть start_param = токен
        → GET /api/me  (заголовок X-Telegram-Init-Data)
        → сервер: проверка подписи → users (найти/создать) → если есть токен — вступить в группу
        → ответ: кто я, роль, группы, что ещё нужно (ФИО, согласие)
```

**Проверка `initData`** (`api/_lib/auth.ts`):
- `secret = HMAC_SHA256(key="WebAppData", data=BOT_TOKEN)`;
- строка проверки — все поля кроме `hash`, по алфавиту, `key=value` через `\n`;
- `HMAC_SHA256(secret, строка) == hash` (сравнение за постоянное время);
- `auth_date` не старше 24 часов;
- `initDataUnsafe` и `username` для личности **не используем** — только `user.id` из проверенной строки.

**Приглашение** (`invites`): одноразовое. Вступление — одним запросом `update invites set used_by=…, used_at=now() where token=… and used_by is null and (expires_at is null or expires_at > now()) returning group_id, role, full_name` → если строка вернулась, создаём `group_members`. Повторное открытие той же ссылки просто открывает приложение. Чужой использованный токен → понятная ошибка «приглашение уже использовано».

**Первый вход:**
- ФИО (`full_name_source = 'self'`) и год рождения → `POST /api/me`;
- согласие на обработку ПД → `POST /api/consent` (`kind = personal_data`, `doc_version`, `granted_via = telegram`, копия `telegram_user_id`);
- младше 18 → дополнительно родительское согласие; его вносит преподаватель (`granted_via = paper/teacher`). Пока его нет — ❓ решить: пускать к урокам или нет.

**Бот** (`api/bot.ts`, вебхук с проверкой `X-Telegram-Bot-Api-Secret-Token`):
- `/start` и `/start <токен>` → сообщение с кнопкой `web_app`, открывающей Mini App (токен передаём дальше через `startapp`);
- `/help` → коротко, как пользоваться;
- остальное — подсказка открыть приложение.

## 2. Уроки, ответы, прогресс (#6)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/me` | Профиль, роль, группы, `ui_language`, что не заполнено. Принимает `start_param` (вступление по приглашению) |
| POST | `/api/me` | ФИО, год рождения, язык интерфейса |
| POST | `/api/consent` | Согласие на обработку ПД |
| GET | `/api/lessons` | Опубликованные уроки + прогресс студента |
| GET | `/api/lessons/:id?lang=kk` | Урок без серверных полей; язык: `kk` из `lesson_translations` (если `approved`), иначе основной |
| POST | `/api/answer` | Проверить ответ, записать `attempts`, обновить `progress` |
| POST | `/api/hint` | Следующая подсказка (лестница 1→2→3), запись в `hint_events`; в самостоятельной задаче — отказ |
| POST | `/api/help` | Обращение «нужна помощь» → `help_requests` (+ уведомление преподавателю, позже) |

**Что вырезается из урока перед отправкой в браузер:** `expected`, `tests`, `solution`, `number_part.expected`, `variants`, `free_input`, `common_mistakes.pattern`. Остаётся то, что студент видит: тексты, `options`, `hints` (выдаются по одной через `/api/hint`), `checks` (таблица кассы и так показывает ожидаемое).

**`POST /api/answer`** — тело `{ lesson_id, step_id, answer, request_id }`:
- `choice` — индекс; `number` — `|ответ − value| ≤ tolerance` с тем же разбором чисел, что в прототипе (пробелы, ₸, м², кв.м…); `number_part` — обе части должны быть верны;
- самостоятельная задача: вариант выбирает **сервер** (детерминированно по студенту и уроку), браузер получает только тексты своего варианта;
- `request_id` (uuid от клиента) + `unique (user_id, request_id)` — повтор запроса не создаёт дубль;
- ответ: `{ correct, feedback, progress }`, где `feedback` — из `success` / `common_mistakes` / общий;
- пишем `attempts.language` и `is_independent`; в прототипной фазе результаты из браузерной проверки помечаем отдельно (решение по #7).
