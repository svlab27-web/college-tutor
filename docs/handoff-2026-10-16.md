## 4. Как работать

**Тесты** — локальный Postgres 16 (Homebrew), чистая база с миграциями:

```bash
rm -rf dist && npx tsc
```

```bash
createdb -h localhost -p 55432 -U postgres t1 && for f in supabase/migrations/*.sql; do psql -h localhost -p 55432 -U postgres -d t1 -v ON_ERROR_STOP=1 -q -f "$f"; done
```

```bash
TEST_DATABASE_URL="postgres://postgres@localhost:55432/t1?sslmode=disable" node --test dist/tests/*.test.js
```

`rm -rf dist` обязательно при смене ветки: старые скомпилированные тесты из `dist/` другой ветки дают ложные падения.

**Стенд** — `node scripts/dev-stand.js .` после `npx tsc`, база `STAND_DATABASE_URL` (по умолчанию локальная `learn`): `http://127.0.0.1:8773/index.html?__tg=<id>`; `__tg=0` — вне Telegram. Студентов и куратора заводить SQL-ом в локальной базе (пример — `tests/lessons-api.db.test.ts`, функция `student`). Уроки на стенд: `DATABASE_URL=<локальная> node dist/scripts/sync-lessons.js`.

**Уроки 02–08** — правка в `scripts/python-month1-lessons.py` → `python3 scripts/python-month1-lessons.py content/python` (сначала все проверки, потом запись) → `npm run lessons:check` → `python3 scripts/plan-doc.py .`. Урок 01 и математику правят в JSON.

**Загрузка уроков в базу** — `DATABASE_URL` в Vercel Sensitive (не посмотреть). Путь без пароля — `npm run lessons:sql` → Supabase SQL Editor, затем `--verify` (docs/api.md п. 3). Копировать только `LANG=en_US.UTF-8 pbcopy`.
