# Как мы работаем

```
Issue → ветка → код → Pull Request → ревью → Squash and merge → автодеплой
```

## Правила

1. В `main` напрямую не пушим — только PR с одобрением второго человека.
2. Одна задача — одна ветка — один небольшой PR. В описании `Closes #N`.
3. Ветки: `feature/…`, `fix/…`, `content/…`, `db/…`, `docs/…`.
4. Коммиты: `feat:`, `fix:`, `content:`, `db:`, `docs:` + коротко что сделано.
5. Проверяем PR по превью-ссылке Vercel **на телефоне в Telegram**.
6. Схема БД меняется только новым файлом в `supabase/migrations/`.
7. Секреты — никогда в коде. Утёк — сменить ключ.
8. Решения записываем в `docs/decisions.md`.

## Новая ветка

```bash
git checkout main
git pull
git checkout -b feature/имя-задачи
```

## Новый урок

1. Ветка `content/<предмет>-<тема>`.
2. Файл `content/<предмет>/NN-тема.json` по схеме `content/lesson.schema.json`.
3. PR → ревью → merge.

## Готово, когда

- [ ] PR одобрен и смержен
- [ ] работает на телефоне в Telegram
- [ ] правильный и неправильный ответ проверяются верно
- [ ] нет секретов в коде
